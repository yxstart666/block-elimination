# 方块木语

单页方块消除游戏，提供无限挑战与 30 关闯关模式。深蓝界面、红黄绿蓝紫五色方块、8×8 棋盘，由 Canvas 2D 合成轻量 PNG 图集与动态文字。同一块的所有格子保持同色，从候选区拖动到棋盘后仍保留原色；客户端无运行时第三方依赖，默认离线运行，在线榜单通过可选微信云函数接入。

页面使用确认设计包：顶部设置、居中关卡标题、横向均分对齐的目标，中央宽棋盘，下方三块候选和五项道具；主局不显示分数、评级条、金币余额或额外地图底行。地图、榜单及重新开始从设置进入。道具用完后可通过领取弹窗补充，失败弹窗提供救场。普通候选不加卡片背景；手动提示会标出指定候选和落点。

`assets/ui/` 仅包含运行时的四张 PNG 和图集清单，构建时复制到浏览器及两个微信工程。图集一次加载复用；面板按九宫格绘制，动态数字和文案实时绑定。`src/core/colors.ts` 统一五色语义和旧七色映射。旧 v1 存档只保存进度、评分、金币及库存，没有活跃盘面或目标色，因此保留原记录与存储键。

## 运行与构建

使用 Node.js 24 或以上版本。

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:4173` 试玩。修改 TypeScript 后自动重新打包，刷新页面即可看到变化。

```sh
npm run typecheck
npm test
npm run test:ui
npm run test:powerups
npm run test:tutorial
npm run test:visual
npm run test:levels
npm run test:pacing
npm run test:destructive
npm run test:economy
npm run test:convenience
npm run test:layout
npm run test:design-states
npm run test:timer-vfx
npm run test:rotation-icon
npm run build
```

`npm test` 会先构建，再运行规则、微信适配、激励视频网关和发布脚本模拟测试。`test:ui` 使用 Playwright，以实际鼠标和触摸事件连续游玩，并用独立失败盘面检查结算，同时检查灰态恢复、最高分保存及多尺寸布局；`test:powerups` 检查候选区旋转、落子扣次数、直接换块、失败弹窗广告复活和卸载边界；`test:tutorial` 使用虚拟时钟检查首次教学、空闲手势、错误反馈、暂停恢复及不重复教学。Windows 默认复用本机 Chrome，其他环境可运行 `npx playwright install chromium`，或设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向浏览器。截图保存在 `.local/qa/`。

## 微信开发者工具

`test:visual` 通过真实拖拽检查候选到棋盘的颜色保持、混色三线消除、连消分段画面、粒子上限和特效结束后停止渲染，并验证旧说明按钮位置没有点击入口；截图保存在 `.local/qa/`。

普通小程序是主要交付形式。执行构建后，在微信开发者工具中导入 `platforms/miniprogram`，工程类型选择小程序。无需 npm 构建，无需服务器域名，页面入口是 `pages/game/game`。

另外提供共享相同规则和绘制代码的小游戏工程：导入 `platforms/minigame`，工程类型选择小游戏。

两个工程默认使用 `touristappid` 用于本地查看。预览到微信、上传和提审前，将对应 `project.config.json` 中的 `appid` 替换为自己的相应类型 AppID。工程没有账号、支付或数据采集逻辑；激励视频网关已预留，广告位全部留空，默认不请求广告。正式发布仍需由自己的微信主体完成平台要求的项目配置与审核。

普通小程序通过 `<canvas type="2d">` 挂载，小游戏通过 `wx.createCanvas()` 挂载。读取微信胶囊实际几何位置，将标题与其中心对齐，右上方预留胶囊范围，页面不设说明按钮；状态栏、刘海和底部安全区分别处理。包含 DPR、窗口变化、单指拖拽、后台暂停与卸载释放。平台模拟与浏览器检查不替代微信开发者工具及真机验收。

## 当前游戏规则

- 当前页面是无限挑战，没有目标分数或达到分数自动通关。持续累积分数，直到所有剩余候选均无法放置才结束；最高分在浏览器／微信本地保存，重新挑战和重新打开后保留。重新挑战入口仅位于失败弹窗。
- 本机首次进入时提供教学三块候选：2×3 竖块、2×2 方块、3×2 横块。棋盘上下各有一片 6×2 木块，只有 2×2 方块能放入中央缺口。开局不显示手势或高亮正确候选，让玩家先自行比较；空闲 4 秒后才出现手势，任何操作都会收起并重新计时，选错只给轻提示。放入正确木块后同时消除两行，在原棋盘补充正常三块候选继续挑战，教程得分保留。紧接教学的首批提供两块竖双格与一块方形／矩形，通过正常落子可以再消两行，减轻残留木块压力；这组安排只用于首次教学衔接。教学出现后立即在本地保存标记；再次打开或失败后重新挑战均从空棋盘、零分和正常三块候选开始，不重复教学。浏览器与两个微信入口分别保存标记，存储受限时仍能正常玩，当前页面内重新挑战始终跳过教学。
- 拖动候选木块到空格，也可以先点选木块，再点击其左上角落点。
- 木块默认保持方向，可使用旋转道具改变方向。填满整行或整列会同时消除，其他木块留在原位。
- 正常三块一组，当前组全部使用后才补下一组。无限挑战采用每局种子驱动的混合供牌，不再固定六组循环。长条、矩形、小 L、大 L、四格 K 型折块及四格 T 混合，加入低频 3×3 方块；普通供牌避免单格和同族重复占多数，拥挤盘面可用单格补位。开局前三组不发四格、五格长条，前两组不发 3×3；每组最多一根三格以上直条，四格、五格长条不连续两组出现，每组最多一个长条或 3×3 难块。新一组三块根据当前盘面规划，至少存在一种顺序可以全部合法使用；规划优先补齐行列、减少孤立空格，拥挤时允许小块救急。玩家仍需选择落点与顺序；相同种子与相同落子序列可以复现供牌。K 型为常规四格折块，T 型为 `### / .#.`，不加入斜角或六格分叉。
- 正常玩法中，整个棋盘都没有落点的候选会变灰并无法拿起；消除腾出空间后实时恢复。还有任意一块可放就继续游戏，不提前补牌。三选一教学保持三卡中性，供玩家先自行判断。
- 每次落子 10 分，每消一条线 20 分；连续落子均有消除时，从第二次起额外获得 `10 × (连续次数 − 1)` 分。未消除的一步会中断连续次数。
- 合法拖拽显示半透明网格吸附，即将填满的行列预高亮；无效落点不产生错误投影，松手回位且不消耗木块。消除反馈包括短暂白闪、沿行列移动的彩色扫光、碎片／星粒与分数跳动；多线消除及连消强化文字与光效。

规则层仍保留显式 `createGame('goal')` 供原目标关验证使用；默认 `createGame()` 为 `endless`。闯关使用 `createLevel(id)`，不改变无尽模式的供牌和计分。

## 闯关模式

左上设置中的“关卡地图”打开三页选关，每页 10 关。正式版首次只开放第 1 关，通关即解锁下一关，已通关关卡可以重玩；地图提供继续闯关、排行榜和返回无尽入口。实际完成全部 30 关后才显示全通状态。失败后免费重试恢复本关初始棋盘、目标和候选，已消耗的库存不返还。

测试可直接打开 `http://127.0.0.1:4173/?play=levels&unlock=all`。该入口只在本机预览解锁全部选关权限；微信 `develop`／`trial` 版本也开放测试选关，`release`、未知或读取环境失败时保持顺序解锁。测试权限不伪造通关、星级、金币或宝箱；实际跳关胜利仅记录该关，正式入口仍要求补齐前置关卡。

本机浏览器预览默认启用测试便捷模式：广告入口点击即领取，不调用广告网关；金币获取入口直接增加一个道具，不检查余额或扣金币。复活和双倍金币同样跳过广告接口，但保留有效状态及单次领取限制。道具领取后仍按正常操作使用，不自动放置方块。微信开发版／体验版启用相同行为，正式版和未知环境关闭。测试真实广告取消、失败或正常金币扣费时，在本机 URL 加 `test=off`，例如 `?play=levels&unlock=all&test=off`；远端网页不能通过 URL 开启便捷模式。

| 玩法 | 目标 | 规则 |
| --- | --- | --- |
| 消线 | 累计消除本关指定条数的行／列 | 横竖同时消除分别计线 |
| 星星 | 收集本关指定数量的五角星 | 棋盘及后续候选都可带星，所在行／列消除时收集，交叉只计一次；内部字段沿用 `gems` |
| 颜色进阶 | 清除指定颜色的方块数量 | 操作与消线相同，统计实际被清的对应色块；不要求同色相连或配对，含当步新放后被消的方块 |
| 组合目标 | 同时完成两至三项目标 | 消线、星星与颜色数量可叠加，所有目标完成才通关；每关最多三项 |

每关有固定编号 `level-01` 至 `level-30`。第 1、4、7、10 关分别首次引入消线、星星、颜色和组合目标，均为 4 分学习关；机制说明确认后保存一次性标记，重试不重复。学习关通过正常落子尽早给出消除及收集反馈，不强制代放。前期从简单关开始，第 11 关起重复 `66576658665` 的难度波浪。破冰底层规则保留供未来进阶，当前 30 关无冰层或破冰目标。

| 关卡范围 | 设计难度顺序 |
| --- | --- |
| 1—10 | 4、5、5、4、5、6、4、5、6、4 |
| 11—21 | 6、6、5、7、6、6、5、8、6、6、5 |
| 22—30 | 6、6、5、7、6、6、5、8、6 |

学习为 4 分，普通为 5—6 分，困难为 7 分，超难为 8 分；这些分数是设计档位，需要独立试玩继续校准，不表示人类通关率。各档都从留有较多空位、存在多种可行落法的棋盘开始，高难主要来自较长目标和后段的空间规划。前 3 关消线，随后逐步穿插其他机制，第 10 关后最多连续两关同玩法，避免长时间重复同一目标。

组合目标占 13 关：10、11、13、14、16、18、20、22、24、25、27、29、30。穿插消线＋星星、消线＋颜色、星星＋颜色及三项目标，仍保留单目标关调整节奏。30 关全部没有时间限制，仅在剩余候选都无落点时失败，没有隐藏的步数上限。任务栏不保留计时占位，各项目标按等宽列分散对齐，图标与进度保持 4px 间距。消除行列使用专用行列网格图标。

关内按实际目标进度逐渐增加压力：前段优先小块、补齐行列及保留空间；达到约 35% 后逐渐增加形状和规划要求，达到约 75% 后进入收尾。每关另有最低热身步数，避免刚开场就切入高压阶段。组合关以各项目标完成比例的平均值判断阶段，超额收集不提前推高难度。供牌仍会保留当前组三块的一条完整合法路径，长条限制继续生效；不会为触发广告故意发无解牌。

当前组三块全部使用才根据实际棋盘、目标进度和种子补下一组；同一关、同一落子序列可重现供牌，换一种落法会得到相应的盘面适配。收集关会持续发带星方块，颜色关会持续提供尚未完成的目标色。星星随方块旋转，换块后保留星星，刚放下就消除也能收集。目标达成即胜利；未完成且所有剩余候选无处放置时结束。验证路线结束不会令实际供牌耗尽。

正式关卡统一使用 `timeLimitSeconds:null`，不启动时钟，也不因等待、后台经过时间或操作次数而失败。难度来自收集目标、形状组合和后段空间规划，保留开局消除体验与难度波浪。`maxMoves` 仅为离线验证／排行榜合理分数上界的估计；规则层保留旧计时和步数夹具的兼容，正式关卡不使用。

广告复活保留目标和当前盘面，只移除普通阻挡，保护未收集星星与未达标颜色，不直接增加目标进度。无法腾出位置时不请求复活广告。关卡分数不写入无尽最高分。返回无尽模式恢复本次进入闯关前的棋盘、分数及原道具次数；无尽失败后的重新挑战仍为空白棋盘。

通关和已学习记录用 `wood-blocks.campaign.v1` 在本地保存，浏览器存 JSON、微信存对象，版本为 1。未知关卡、重复项和损坏存档安全过滤；解锁要求所有前关完成，存档中的后关孤立记录不能跨关解锁。重新打开定位到最早未通关关卡，未完成的局面从本关初始状态开始。存储不可用时，本次会话依然可正常解锁和学习，不阻断游戏。最高分、无尽教学标记与闯关进度分别保存，不互相覆盖。

颜色与组合的新说明使用 `level-07:colors-v1` 和 `level-10:colors-stars-v1` 学习标记；保留旧版通关记录和旧说明标记，首次遇到新机制时补充一次说明，不清空进度。

数据与不对玩家显示的验证路线位于 `src/core/levels.ts`，全部路线可无道具通关；保存的牌组是该路线的重放证据，实际玩家无需遵循这条路线。`tests/levels.test.ts` 用独立几何模拟核对 30 条路线、玩法轮换、难度波浪、收集和终局边界；`npm run test:levels` 以真实指针检查关卡、学习、进度及无尽隔离，截图保存在 `.local/qa/`。`node scripts/author-levels.mjs` 在开发阶段确定性重建关卡，`--verify` 只核验已保存路线、不修改数据；正式运行只在补牌时对当前盘面做有限三步规划。独立可见牌组策略用于比较开局可选落法、早期消除、流程长度及失败时的目标进度，不读取验证答案，其结果不代表人类通关率。

## 星级、金币与关卡宝箱

仅通关后评星，结算、最佳成绩与排行榜均使用实际落子、消线及连击所得分数，没有时间奖励。炸弹或推土机完成目标也使用同一胜利结算。

每关 `starScores` 记录一至三星分数线，通关至少一星；二星约为已验证路线纯得分的 70%，三星线取验证路线的实际纯得分。所有关卡都有无需道具的三星路线，星级分布仍需独立试玩校准。地图保留历史最佳星级、分数和已领取奖励，不重复发放。

| 历史最高星级 | 该关累计基础金币 | 首次奖励 |
| --- | --- | --- |
| 一星 | 10 | 金币 |
| 二星 | 15 | 金币 |
| 三星 | 40 | 金币＋一个关卡宝箱 |

奖励不可重复领取；一星升二星只补 5，二星升三星只补 25。每关首次三星宝箱随机发提示、旋转或换块 1 个，不发炸弹或推土机。重玩同星级、降低星级或只刷新分数均不重复发币或宝箱。通关弹窗可完整看广告，将本次新增金币再补同额一次，最多额外 40；不复制宝箱。广告中断、出错、不可用或重复回调不发奖励。

`wood-blocks.economy.v1` 独立保存金币、五种道具库存、每关最佳分数与已领奖星级，以及去重／翻倍领取记录。初始提示、旋转、换块各 3 个，炸弹和推土机为 0；库存跨关保留，重试不会恢复库存。金币用于道具领取弹窗内购买，当前无付费充值入口。

## 道具与激励视频

无尽及闯关局内均显示提示、旋转、换块、炸弹和推土机，使用时扣一个库存；库存为空时可完整看广告获得一个，或使用金币购买。领取后再点击道具使用。失败弹窗保留炸弹、推土机与复活入口。

| 道具 | 效果 | 本局次数与奖励 |
| --- | --- | --- |
| 提示 | 标出具体候选及对应落点，不自动落子、不消耗步数 | 扣库存 1；购买价 10 金币 |
| 换块 | 直接将剩余候选变单格，已用槽位不补；全为单格时不消耗 | 扣库存 1；购买价 20 金币 |
| 旋转 | 开启模式后点候选试转，实际放下转向方块才扣；退出恢复未放方向 | 扣库存 1，试转与对称块不扣；购买价 15 金币 |
| 炸弹 | 随机清除完整 3×3 区域，均匀选择有方块／冰层的有效区域，不炸空区 | 有效使用才扣库存 1；购买价 30 金币 |
| 推土机 | 清除棋盘底部三排（第 6—8 行） | 有效使用才扣库存 1；购买价 40 金币 |
| 复活 | 失败弹窗点击“看广告复活”，完整观看后清理让现有候选重新可放所需的最少障碍，保留分数 | 每局最多成功一次；未配广告、播放中断或错误均不复活 |

旋转入口及候选标记共用无方块装饰的冰蓝粗双弧箭头。底部按钮保持静止；进入旋转模式后，候选上的 50% 透明标记持续顺时针缓转（每圈约 1200ms），退出模式、打开菜单或结束关卡后停止。对称／无效试转不改变方块，也不扣库存；实际放下改变方向的方块才扣一次。

换块的单格效果参考所提供视频 133～135 秒的稳定画面；该视频只演示了一次换块，不能据此断言原作所有换块结果。正常供牌与道具救急分开，不会因换块机制而在正常牌组中大量发单格。

道具不增加积分、消除线数、落子或连消统计。炸弹、推土机命中的星星和对应颜色计入目标，未来冰层也可移除；仍需所有目标完成才通关。时间耗尽时不能靠救场恢复预算，不请求无效广告。炸弹以抛物线投向实际随机区域，命中后清除并扣一次库存；推土机模型约三列宽，铲头经过一列就立即清除该列底部三排、爆裂并更新收集，后面的列保持原状，首次有效清除只扣一次库存。扫除各阶段从同一原盘面计算累计进度，避免重复收集。动画期间防止重复操作，重开／销毁取消后续效果，不能影响新局；已经产生的有效清除不返还库存。退出试转、无效落点、视频中断或出错均不消耗次数或库存。

广告位在 `src/config/ads.ts` 中配置，七个入口为 `revive`、`refresh`、`rotate`、`bomb`、`bulldozer`、`hint`、`doubleCoins`，当前全部留空。填入正式微信 AppID 下的真实 `adUnitId` 后重新构建，可共用同一广告位。浏览器没有微信广告 SDK，视频入口明确提示不可用；不会免费触发救场、双倍金币或模拟完成。

`src/services/rewarded.ts` 统一管理正式广告请求，只有关闭回调 `isEnded === true` 才报告完成。加载或打开失败会恢复可操作状态；同一时间只允许一个奖励请求，后台暂停不会丢弃在播广告，页面销毁则取消等待并解绑。空 ID 不创建广告实例、不请求广告。测试便捷模式在调用网关前直接返回测试完成结果；正式环境不启用该分支。

浏览器还支持数字键 1–3 选择木块、方向键移动落点、Enter 放置、X 换块、T 旋转、V 复活、Escape 取消；旋转模式可用数字键试转候选，再以方向键选择落点并回车放下；再次按 T 或 Escape 退出。L 打开闯关地图，左右方向键翻页，数字 1–9 和 0 选择本页第 1—10 关，Enter 继续闯关，Escape 关闭。学习说明按 Enter／Escape 或点击确认按钮关闭。无尽局面保留在本次页面会话，重新打开从头开始；本地进度独立存储，只有启用真实榜单配置后才提交闯关成绩。

## 排行榜接入

地图和关内入口可查看全体用户与好友页，支持单关最高分和各关最高分累计总榜。同一成绩不重复累加，同分按先达到时间排序。该规则独立定义；公开资料不足以证明与开心消消乐的所有排名细节一致。

当前未提供正式微信 AppID／云环境，`src/config/leaderboard.ts` 默认关闭，榜单显示未连接和本机最佳分，不生成假用户、假好友或假排名。可选后端、索引、权限与身份校验见 [云函数接入说明](cloudfunctions/leaderboard/README.md)。普通小程序不能直接读取小游戏开放数据域的微信好友分数；当前明确显示未接入。小游戏已有开放数据域画布接入，启用真实配置后才能展示同玩好友。普通小程序若需要好友关系榜，仍需额外接入用户主动邀请／添加的好友关系服务。

## 后续玩法研究

当前仅保留方案，不进入前 30 关：钥匙开锁（先取得钥匙释放锁区）、信箱收件（在目标旁制造消除）、铺色扩散（从已有色源向被消除区域扩散）。迁移后的 8×8 规则需另做学习关验证；破冰也留作未来进阶。

原机制参考 [Candy Crush 钥匙障碍](https://candycrush.zendesk.com/hc/en-us/articles/360000754717-Which-Blockers-can-I-find-in-the-game)、[Royal Match 信箱](https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/354-mailbox/)、[Candy Crush Soda 果酱模式](https://candycrushsoda.zendesk.com/hc/en-us/articles/115000941085-What-are-the-different-game-modes)；这些来源支持原作机制，本项目迁移设计不等同于原作规则。

对新录屏经典模式 16 组、48 块可见供牌的统计：直条约 33%，五格以上约 40%，四格约 40%，三格以下约 21%；3×3 出现 5 次。这里只作为本作混合供牌的调参依据，不代表原作完整概率或隐藏算法。本作根据试玩反馈采用盘面自适应供牌：先在虚拟棋盘按真实规则规划三步，再打乱三块候选的显示顺序；优先可消除、少留孤洞的组合。方块比例随盘面空隙和补行机会变化，不用固定空盘抽样比例代表实际难度。规划搜索有固定宽度和候选上限，只在整组补牌时运行，不在绘制帧中运行。棋盘尺寸与录屏相同，为 8×8。

规则层不使用 DOM 或微信 API。开发工具仅有 TypeScript、esbuild 和浏览器测试用的 Playwright；正式运行无需游戏引擎。等待手势提示时只使用一个空闲定时器，手势运动结束后转为静态。正式挑战的静止页面停止请求动画帧，拖拽、消除和短暂反馈才触发重绘。

交互与视觉反馈参考用户提供的操作视频，积分及供牌在本项目中独立定义。公开玩法资料见 [Google Play：Block Puzzle: Block Smash Game](https://play.google.com/store/apps/details?hl=en_US&id=com.miracle.block.smash.journey)。微信接入参照[官方 Canvas 2D 示例](https://github.com/wechat-miniprogram/miniprogram-demo/tree/master/miniprogram/packageComponent/pages/canvas/canvas-2d)与[官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)。
